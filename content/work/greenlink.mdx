## Problem
Traditional environmental telemetry architectures rely on continuous high-bandwidth cloud uplinks, which fail in remote or intermittent network conditions and incur prohibitive transmission latency.

## Objectives
- Deploy low-power sensory nodes capable of local edge inference.
- Maintain persistent buffering during connectivity outages.
- Provide sub-second alerting for localized environmental threshold anomalies.

## Architecture
The system consists of distributed hardware sensor nodes communicating over a local mesh/MQTT broker, feeding into an on-premise gateway running FastAPI and a lightweight time-series storage engine.

```
[ Sensor Node (MCU) ] ---> (MQTT) ---> [ Edge Gateway (FastAPI) ] ---> [ Telemetry DB ]
                                                 |
                                         [ TFLite Inference ]
```

## Tech stack
- **Edge Inference:** TensorFlow Lite / Micro
- **Ingestion & API:** FastAPI, Pydantic, Python 3.12
- **Protocols:** MQTT, WebSockets
- **Containerization:** Docker multi-stage builds

## Engineering decisions
- **MQTT over HTTP Polling:** Reduced payload overhead by 68% and enabled instantaneous pub/sub notification.
- *Rejected Alternative:* Direct HTTP REST post from edge MCUs was rejected due to socket handshake overhead and memory consumption on microcontrollers.
- **SQLite/DuckDB Edge Buffer over Direct Remote Sync:** Isolated nodes from cloud latency and preserved telemetry integrity during disconnects.
